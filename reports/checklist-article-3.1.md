## A. Содержание, которое должно быть в 3.1

### A1. Каркас выбора

- [ ] В кратком ответе зафиксирован порядок: частоты/полоса → роль звена (борт/земля, TX/RX) → нужные направления → поляризация (со ссылкой на 3.3) → тип и диаграмма → согласование/фидер (ссылки на 3.4–3.5) → проверка установленной системы.
- [ ] Явно сказано: имя типа не доказывает пригодность для данного аппарата или станции.
- [ ] Есть отдельный блок «типичные вопросы агенту» с ответом «нужны данные» для совместимости, дальности и «какую купить».

### A2. Типы конструкций (каждый пункт — для всех восьми типов или с явным «не рассматривается»)

Для диполя, монополя, patch, cloverleaf, helix, Yagi-Uda, рупора/отражателя, решётки:

- [ ] Устройство без численных характеристик конкретного изделия.
- [ ] Типичная ориентация / сектор (качественно): где максимум, где провалы.
- [ ] Когда тип обычно рассматривают на **борту** vs на **земле** (качественно, без обещания дальности).
- [ ] Ограничения и запрещённые выводы (не менее одного «нельзя» на тип).
- [ ] Локатор первоисточника (раздел/страница), согласованный с `sources.yaml`.

Дополнительно проверить покрытие пробелов текущего текста:

- [ ] Cloverleaf: зачем смотреть направление вращения — одной фразы + ссылка на 3.3 достаточно; не разворачивать теорию CP здесь.
- [ ] Helix: осевой vs нормальный режим; «витой штырь ≠ осевая CP-спираль».
- [ ] Patch: «панельная» маркировка ≠ известная конструкция внутри.
- [ ] Решётка vs diversity / несколько антенн модема — различие сохранено и усилено примером «две антенны на плате ≠ фазированная решётка».
- [ ] Yagi / рупор: роль преимущественно наземной направленной установки; для подвижного борта — оговорка о наведении.

### A3. Слой «БПЛА», который уместен именно в 3.1

Не каталог FPV-рецептов, а условия выбора типа:

- [ ] Различены роли: бортовая антенна (меняется ориентация) и наземная (часто сектор/наведение).
- [ ] Упомянуто, что управление, видео и телеметрия могут требовать **разных** антенн/трактов; детали каналов — в 5–7, здесь только следствие для выбора типа.
- [ ] Крен/тангаж/рысканье: смена направления относительно провалов диаграммы и оси типа — качественно; расчёт ориентации — не здесь.
- [ ] Экранирование корпусом / соседними элементами: «меняется окружение типа» + ссылка на 3.5 / 3.2, без методики измерения.
- [ ] Запрет: не выводить радиус связи из типа антенны.

### A4. Практический блок

- [ ] Чеклист ошибок сохранён и не противоречит A1.
- [ ] Учебный пример остаётся условным (без выдуманных дБи, км, моделей).
- [ ] В конце — карта ссылок: 3.2, 3.3, 3.4, 3.5, 2.1, 9.1 (и при необходимости 4–6 одной строкой).

## B. Чего в 3.1 быть не должно

- [ ] Нет таблиц усиления, КСВН, дальности «типичных» антенн без паспорта.
- [ ] Нет рекомендаций конкретных брендов/артикулов (это 13.x после источников).
- [ ] Нет формул длины/усиления/потерь (реестр формул + 8.x / 3.2 / 3.4).

## D. Критерий «достаточно для агента» только по зоне 3.1

Считать 3.1 содержательно готовой к ревью (не к `verified` и не к `rag.include: true`), если агент при опоре на одну эту статью плюс указанные ссылки:

1. Различает восемь типов и не путает diversity с решёткой.
2. Объясняет порядок выбора типа без обещания дальности.
3. Для борта vs земли указывает qualitatively разные риски ориентации.
4. На вопрос «какая антенна лучше / какой радиус» отвечает отказом с перечнем недостающих данных.
5. Не подменяет ответ материалом 3.2–3.5, а отсылает к ним.
