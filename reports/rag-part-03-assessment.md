# Проверка пригодности части 3 для RAG

Дата: 2026-10-31. Проверяющий: автоматизированный исполнитель Codex. Речь идёт о локальном снимке; изменения раздела 03 ещё не опубликованы на GitHub.

## Вывод

Часть 3 содержит полезную основу для ответов на вводные вопросы об антеннах и кабелях. Она **ещё не готова как основной проверенный RAG-корпус**: пять статей имеют `draft`, `rag.include: false`, а основной экспорт отключён. Доступна только исследовательская выгрузка целых документов с предупреждением о статусе. Содержательная проверка другим специалистом и испытание ответов конкретного агента не проводились.

## Исходная проверка 15 вопросов до добавления расчётов

- Пятнадцать вопросов записаны в [контрольном наборе](../rag/evaluation/part03-questions.json). Для каждого указаны ожидаемые документы, опорные факты, ограничения, недопустимые выводы и необходимость ответа «недостаточно данных».
- Для 13 вопросов, на которые в черновиках есть материал, запущен простой лексический поиск по всем 27 статьям исследовательской выгрузки: 13 из 13 имеют ожидаемый документ в первых пяти результатах; 12 из 13 — в первых трёх; 11 из 13 — на первом месте. Это результат одного небольшого специально подготовленного набора, не независимой выборки.
- Два вопроса требуют ответа «недостаточно данных»: совместимость и дальность неизвестной системы; выбор неизвестного RG-174 на 5,8 GHz. Для второго поиск нашёл статью с ограничением паспорта конкретного изделия; способность модели корректно отказаться от обобщения не испытывалась. Эти два вопроса исключены из знаменателя показателя поиска.
- Качественно рассмотрены соответствия текстов ожидаемым опорным фактам: различие типов антенн, поляризация и измерение отражений; условия табличного затухания LMR-195/240/400 при 900 MHz и ограничения для RG_174_/U. Это проверка наличия сведений в тексте, а не независимая сверка каждой ячейки с первоисточником при данном испытании.

## Как воспроизвести текущую проверку

Из корня проекта с Python 3.10 или новее:

```text
python -m scripts.export_rag --research
python rag/evaluation/check_part03.py
```

Экспорт генерируется в `build/research.jsonl`. Поиск использует простые частотные веса по словам, приближённое усечение русских слов до пяти символов и полный текст статьи как один документ; при равном счёте сортирует по ID. Результаты печатаются в JSON, время не включается. Текст вопроса, ожидаемые ID и сами статьи созданы в рамках одной задачи: лексический показатель может быть завышен. Это не BM25, не семантический поиск и не тест генерации ответов.

## Какие вопросы база уже поддерживает

- Общие типы антенн, основные конструкции и типичные ограничения — статья [о типах](../docs/03-antennas/antenna-types.md).
- Диаграмма, различие gain/directivity/realized gain и условия сравнения — [диаграмма и усиление](../docs/03-antennas/pattern-gain.md).
- Виды поляризации, влияние ориентации и неоднозначность диагностики — [поляризация](../docs/03-antennas/polarization.md).
- Смысл S11, return loss, КСВН и влияние измерительной плоскости — [согласование](../docs/03-antennas/matching-vswr.md).
- Выбор по паспортным примерам кабелей, частоте, температуре, длине и изгибу — [размещение и кабели](../docs/03-antennas/placement-cables.md). Ответ должен сохранять производителя, артикул, частоту, единицы и условия паспорта.

## Пробелы, выявленные при исходной проверке

1. Формулы преобразования КСВН, return loss и S11 и пересчёта потерь на длину кабеля ещё не зарегистрированы и не протестированы. Агенту нельзя обещать проверенные расчёты по этим зависимостям только на основе текущих статей.
2. Нет подтверждённых карточек реальных антенн и измерений установленной сборки: без конкретных моделей и условий нельзя надёжно назвать совместимость, диаграмму, усиление или дальность.
3. Нет проверенной методики, тестового набора и результата для семантического поиска и генерации. Не проверены точность цитирования, следование ограничениям, устойчивость к противоречиям и ответ «недостаточно данных» работающим агентом.
4. Экспорт не сохраняет структурированные локаторы каждого утверждения, не разбивает длинные статьи по смыслу и не реализует манифест или удаление устаревших фрагментов. Полные статьи увеличивают объём контекста и могут скрывать нужное условие.
5. Автоматическая проверка метаданных не доказывает правильность содержания. Статьи и новые паспортные таблицы ожидают содержательного ревью; правила применимости нормативов и совместимость конкретных разъёмов требуют отдельных источников.

## Дополнение после исправлений

Добавлены зарегистрированные реализации и тесты формул `reflection-vswr`, `return-loss-reflection` и `uniform-cable-attenuation`; статьи о согласовании и кабелях дополнены примерами и условиями. [Протокол проверки расчётов](verification-part03-calculations.md). Замечание 1 выше закрыто в части указанных моделей, но человеческое техническое ревью не проведено. Пункты 2–5 остаются открытыми.

Контрольный набор расширен до 18 вопросов, включая два численных примера и вопрос с недостаточными данными о комплексном импедансе. В той же лексической конфигурации ожидаемый документ найден в первых пяти для 15 из 15 вопросов с достаточной информацией, в первых трёх — для 14 из 15, на первом месте — для 13 из 15. Три вопроса с недостаточными данными исключены из знаменателя. Это проверка поиска, а не оценка реального ответа агента; модель не испытывалась.

Следующий шаг: провести содержательное ревью, включая паспортные значения, и проверить реальные ответы выбранного агента с цитатами и отказами при недостатке данных. Основной экспорт, структурированные локаторы и независимый тестовый набор остаются незавершёнными.
